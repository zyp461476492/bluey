## 09:40 架构方案：AI 主 + OpenMoji 辅，新增 Studio 生产端

**用户决定**
1. 素材：AI 手绘为主，OpenMoji 为辅助（额度不足或人工指定时降级）
2. UI 框架：可以引入成熟框架，可本地部署
3. 需要一个题库（图片生成）生成器 + 素材信息维护，本地单机单节点，JSON 或 SQLite

**核心架构判断：双制品分离**
- `app/`（运行端）保持零构建纯静态 —— 否则孩子设备上要 npm install，TV 打不开
- `studio/`（生产端）用现代栈 —— Node + Express + node:sqlite + Vue3 + Element Plus
- 依赖方向单向：`studio → data/ + assets/ → app`；删掉 studio，app 照常跑
- ADR-001/002 不废除，**适用范围收窄到 `app/`**

**最关键的一条现实约束（容易设计错）**
- 本机生图挂在 agent 工具上，**不是 HTTP API**，Studio 点按钮无法直接出图
- 解法：生成抽象成"工单（job）"，executor 可插拔（agent / api / manual / library）
- agent 模式：Studio 写 outbox JSON → agent 执行 → 写 inbox JSON → Studio 导入
- **job 清单是文件不是内存**，所以崩溃/换天/额度用完都能接着跑

**存储决策**
- SQLite 是工作库（状态机、额度账本、覆盖率查询、phash 去重、并发写，JSON 一项都撑不住）
- JSON 是发布产物，只由 `publish` 单向导出
- 铁律：Studio 不读 data/questions；App 不读 studio.db

**新增文件**
- `docs/10-studio-architecture.md`（约 400 行，含 6 张表 SQL、状态机、策略链、分阶段）
- `studio/README.md`（占位，三条边界 + 端口）
- ADR-009 双制品分离 / ADR-010 SQLite 工作库 / ADR-011 策略链与混源规则 / ADR-012 技术栈

**修正的旧结论**
- ADR-008 的"先 emoji 后 AI"顺序作废（优先级反转），来源与规格部分仍有效
- "同分类不混源"改为"混源不是事故，无意识的混源才是"，并加 `provisional` 标记与混源报表

**本机环境实测**：node v22.22.2 / npm 10.9.7 / python 3.13.14 / sqlite3 3.53.1；
无 pnpm、无 sqlite3 CLI。→ 用 `node:sqlite` 内置模块，避开 Windows 原生编译。

**下一步建议**：先做 M1（App 主循环，用现有 12 张打样图），再做 S0–S1。
理由：孩子愿不愿意玩才是最大未知数；Studio 的收益要等词条数 > 50 才显现。

## 10:35 修"有中文没英文" + 完成 M2（年龄档与三模式）

### 一、语音问题定位（用户问"是不是程序老"）

**不是程序老，是我写错了。** 实测本机语音包：

| 类型 | 已装 |
| --- | --- |
| SAPI5（Chrome 用） | Microsoft Zira - en-US、Microsoft Huihui - zh-CN |
| OneCore（Edge 自然语音） | 仅 zh-CN：慧慧 / 康康 / 瑶瑶，**无英文** |

代码里把英文写死 `en-GB`，系统只有 `en-US` → Chrome 找不到匹配语音就静默不出声；
中文 `zh-CN` 对得上所以正常。

**修法**：`u.lang` 必须写**实际选中语音的 lang**，不是"我想要的 lang"。
选语音顺序：完全匹配 → 同语种不同地区 → 该语种任意 → null。
另外首次调用时语音列表可能为空（异步填充），加了最多 600ms 的等待。

**新增 `tools/voice-check.html`**：列出这台机器上浏览器实际能用的语音，
并给出"没有英文语音"的安装指引。以后遇到"没声音"先开这个页。

**这一轮改了什么（不赌单一原因，全部加固）**
1. `u.lang` 只用**实际选中语音**的 lang；`voice.lang` 做 `_`→`-` 归一化，

2. **cancel → speak 竞态**：检测到引擎还在说话时，先 cancel，等 140ms 再 speak；
   每次尝试之间再隔 60ms
3. 每次尝试加 **700ms 内必须 onstart** 的判定，没开始就换下一种方案（最多两轮），
   避免"系统根本没英文语音"时傻等 2.7 秒才轮到中文
4. `stopEngine()` 与 `cancel()` 分开——cancel 会 bump sessionToken，
   内部重试时误用会让自己的 token 失效、所有方案被跳过（差点写成死锁）
5. 首次朗读打一条 `console.info`，输出可用语音总数与解析出的中英文语音
6. 新增 `ui/toast.js` + 家长提示：检测到「有语音但没英文语音」时提示一次，
   指向 `tools/voice-check.html`

**`tools/voice-check.html` 重写**：改成直接 import `app/src/ui/speech.js`，
