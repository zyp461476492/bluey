# 01 产品愿景

## 一句话

**Bluey 是一个看图猜词的双语启蒙游戏：一张图出现，孩子想一想，5 秒后答案揭晓——不需要认字，不需要打字，打开就能玩。**

## 要解决的问题

现有的儿童英语 / 识字 App 普遍有三个问题：

1. **重**：要注册、要会员、要家长陪、动辄几百 MB 包体和一堆动画关卡。
2. **门槛在"操作"而不是"认知"**：孩子还没学会拼写，App 却要求点选、拖拽、跟读打分。
3. **屏幕单一**：手机 App 投不到电视上；电视上的儿童应用又要单独一套。

Bluey 的选择是：**把交互削到只剩"看"和"说"**。图片负责吸引注意力，
5 秒静默负责留出思考时间，答案揭晓负责给反馈。其余全部砍掉。

## 目标用户

| 角色 | 描述 | 诉求 |
| --- | --- | --- |
| 主要使用者 | 3–8 岁儿童 | 画面大、图好看、有反馈、不用认字 |
| 决策者 / 陪伴者 | 家长（25–45 岁） | 不注册、不联网也能用、内容可控、别太吵 |
| 次要使用者 | 双语启蒙阶段的低年级学生 | 中英对照，能听到发音 |

## 使用场景

- **客厅电视**：饭后十分钟，家长用遥控器开一局，孩子坐在沙发上大声猜。
- **平板**：亲子共玩，孩子用手点"下一个"。
- **手机**：出行途中的碎片时间，竖屏单手可操作。

## 产品原则

1. **零文字门槛**：孩子不看说明也能玩。按钮用图标 + 大尺寸，不靠小字提示。
2. **思考时间不可压缩**：5 秒倒计时要可见（进度环），可以跳过，但不许自动加速。
3. **错误不惩罚**：没有分数、没有排行、没有"答错了"的红叉。猜错只是揭晓答案。
4. **家长 30 秒内看懂**：设置项不超过一屏，术语用大白话。
5. **离线优先**：飞行模式下功能完整，这是信任的基础。

## 成功标准

初版（M1–M3 完成）达成以下即算成功：

| 指标 | 目标 |
| --- | --- |
| 上手成本 | 孩子首次使用 10 秒内能自己进入第一题 |
| 三端可用 | 电视 / 平板 / 手机 各跑 20 题不出现布局错乱 |
| 题库扩展成本 | 新增一个词条 = 加一段 JSON + 放一张图，不改代码 |
| 离线完整 | 断网后全流程可用 |
| 内容门槛 | 家长能在 5 分钟内自己加 10 个词（改 JSON 或用后续的题库编辑器） |

## 使用边界（重要）

**本项目定位为家庭内部使用，不涉及商业。**

这条边界带来两个直接影响，写在这里以免后来者反复讨论：

| 影响 | 说明 |
| --- | --- |
| 素材授权可以放宽 | 允许使用 CC BY-NC（禁止商用）类素材，如 ARASAAC；允许使用需署名的免费素材 |
| 但对**对外传播**敏感 | 把链接发给朋友、发到群里、发到社交平台，就已经越过了"家庭内部"——届时须替换 NC 素材并重新评估名称（见 `docs/09-asset-pipeline.md` §2.4） |

**所以：素材入库时必须在 `assets/SOURCES.md` 标 `可商用 / 需署名 / 仅家用`。**
这一列不是为了现在，是为了"哪天真想发出去"时能一键筛出来。

---

## 非目标（明确不做）

- 不做账号体系、云同步、家长后台
- 不做语音识别打分 / 发音测评（成本高、误判会打击孩子）
- 不做排行榜、社交、分享裂变
- 不做课程体系 / 学习路径规划（至少初版不做）
- 不做服务端渲染、不做 SEO（这是家庭内部工具，不是流量产品）

> 以上非目标是**用来挡需求的**。想加进来必须先改本文件并写 ADR。
