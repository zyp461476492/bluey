# 03 三端交互设计

一套代码、三种物理形态。差异**不在组件库，而在三件事**：观看距离、输入设备、屏幕方向。

---

## 1. 三端差异对照

| 维度 | 电视 TV | 平板 Tablet | 手机 Phone |
| --- | --- | --- | --- |
| 观看距离 | 2.5–3.5 m | 30–50 cm | 25–35 cm |
| 输入 | 遥控器：方向键 + 确认 + 返回 | 触摸（点按 / 轻扫） | 拇指触摸 |
| 方向 | 横屏 16:9 | 横屏为主 | 竖屏为主 |
| 基准尺寸 | 1920×1080 | 1024×768 | 390×844 |
| 字号策略 | 10-foot UI：正文 ≥ 32px，答案 ≥ 96px | 正文 ≥ 20px，答案 ≥ 64px | 正文 ≥ 18px，答案 ≥ 56px |
| 焦点策略 | **必须有可见焦点环**，全部可交互元素可聚焦 | 焦点环仅键盘场景 | 同平板 |
| 最大内容宽度 | 全屏 | 居中，`max-width: 1200px` | 全宽，`padding: 16px` |
| 安全区 | 上下左右留 5%（overscan） | 无 | 避开刘海/手势条 |

> **判据**：靠 CSS 媒体查询 + `pointer` / `hover` 能力检测，不靠 UA 判断设备。

## 2. 主界面布局

### 2.1 猜词主界面（reveal 模式）

```
┌──────────────────────────────────────────────┐
│  ← 返回        分类：动物      ⚙ 设置        │  ← 顶栏，TV 上字号 28px+
├──────────────────────────────────────────────┤
│                                              │
│           ┌────────────────────┐             │
│           │                    │             │
│           │      图片 / GIF     │             │  图片 64vmin 正方形，居中
│           │                    │             │
│           └────────────────────┘             │
│                                              │
│              ◜ 5 ◝   ← 倒计时进度环           │  倒计时在图片下方 8vmin 处
│                                              │
├──────────────────────────────────────────────┤
│          cat      猫                          │  ← 答案区（揭晓前隐形占位）
│        [ 🔊 再听一次 ]   [ 下一题 → ]          │
└──────────────────────────────────────────────┘
```

**关键设计点**

1. **答案区先占位再显形**：揭晓前该区域保留高度但内容不可见（`visibility: hidden`），
   避免揭晓瞬间布局跳动——跳动会让孩子视线丢失。
2. **倒计时是进度环不是数字跳动**：环的流逝比数字更能传达"还剩一点时间"，
   数字只是辅助（3 岁以下不认数字）。
3. **揭晓动效**：图片轻微放大 + 答案区淡入上移，时长 300ms。
   `prefers-reduced-motion` 时退化为纯淡入。
4. **下一题按钮在右下角**，符合遥控器"右→下"的操作直觉。

### 2.2 猜词主界面（quiz 模式）

```
┌──────────────────────────────────────────────┐
│  ← 返回        分类：动物      ⚙ 设置        │
├──────────────────────────────────────────────┤
│        ┌────────────────────┐                │
│        │       图片          │                │
│        └────────────────────┘                │
│        ◜ 5 ◝                                 │
├──────────────────────────────────────────────┤
│   ┌──────────────┐   ┌──────────────┐        │   2×2 网格
│   │  dog   狗    │   │  cat   猫    │        │   每格最小高度 12vmin
│   └──────────────┘   └──────────────┘        │   焦点环 4px 高对比
│   ┌──────────────┐   ┌──────────────┐        │
│   │  pig   猪    │   │  cow   牛    │        │
│   └──────────────┘   └──────────────┘        │
└──────────────────────────────────────────────┘
```

- **2×2 而非 1×4**：电视上单行 4 个会让每个选项过窄，中文 + 英文并排会挤。
- 方向键映射：`←→` 同排切换、`↑↓` 换排、`Enter` 确认。
- 手机上 2×2 改成 1×4 竖排堆叠（拇指够得着，且宽度足够显示双语）。

### 2.3 手机竖屏专项

```
┌──────────────┐
│ ←  动物   ⚙  │
│ ┌──────────┐ │
│ │          │ │   图片：宽度 100%，aspect-ratio 1/1
│ │   图片    │ │
│ │          │ │
│ └──────────┘ │
│    ◜ 5 ◝     │   倒计时：居中
│              │
│  cat   猫    │   答案卡片：从底部滑入
│  [🔊] [下一题]│   按钮高度 ≥ 56px（拇指热区）
└──────────────┘
```

- 竖屏下**图片在上、答案在下**，模拟"翻卡片"的物理直觉。
- 设置面板用底部抽屉（bottom sheet），不使用全屏跳转，避免孩子迷路。

## 3. 响应式实现策略

### 3.1 尺寸单位

**统一用 `vmin` / `clamp()` 做流体缩放**，不用固定 px 断点堆叠。

```css
:root {
  --answer-size: clamp(3rem, 9vmin, 7rem);   /* 答案字号：手机 48px → TV 112px */
  --body-size:   clamp(1rem, 2.2vmin, 1.75rem);
  --tap-min:     clamp(48px, 8vmin, 88px);  /* 最小可点区域 */
  --safe-pad:    clamp(12px, 4vmin, 80px);
}
```

### 3.2 断点（只用于布局形态变化，不用于字号）

```css
@media (max-width: 600px)              { /* 手机：单列 + 底部卡片 */ }
@media (min-width: 601px) and (max-width: 1200px) { /* 平板 */ }
@media (min-width: 1600px), (pointer: none) and (min-height: 700px) { /* TV */ }
@media (prefers-reduced-motion: reduce) { /* 关闭位移类动效 */ }
```

### 3.3 TV 焦点管理（最容易翻车的地方）

| 要求 | 实现要点 |
| --- | --- |
| 焦点可见 | `:focus-visible` 统一 4px 高对比描边 + 外发光，**不用 `outline: none`** |
| 焦点不丢 | 每次渲染后主动 `focus()` 第一个可交互元素，尤其是切题时 |
| 焦点顺序合理 | DOM 顺序即焦点顺序，不用 `tabindex` 打乱 |
| 遥控器返回键 | 监听 `Escape` / `Backspace` → 返回上一级，不退出全屏 |
| 不会误触退出 | 全屏下不拦截系统键，但应用内不设置"长按退出" |

> 电视浏览器对 `speechSynthesis` 支持不稳定，**音频播放失败必须静默降级**，
> 不能因为没声音就卡住流程（详见 `02-requirements.md` F4-3）。

## 4. 交互细节规范

| 元素 | 规范 |
| --- | --- |
| 倒计时总时长 | 默认 5000ms，设置可调 2000–10000ms |
| 倒计时可跳过 | 允许"立即揭晓"（电视：确认键；触摸：点进度环） |
| 切题动画 | 200ms 淡出 → 换图 → 200ms 淡入；无横向滑动（TV 上有人会晕） |
| 按钮最小热区 | 触摸 ≥ 56×56px，TV ≥ 80×80px 视觉尺寸 |
| 颜色语义 | 正确 = 暖绿描边 + ✓；错误 = 不出现红色 ✗，只降低其他选项透明度 |
| 声音 | 揭晓后朗读英文（en-GB）再读中文（zh-CN）；必须有「再听一次」 |
| 背景 | 默认深色；可切浅色（见 §4.1） |

### 4.1 配色主题

两套主题，只换 CSS 变量，不换组件。

| | 深色（默认） | 浅色 |
| --- | --- | --- |
| 页面底色 | `#14100c` 暖黑 | `#faf4e9` 米白 |
| 正文 | `#f7f0e3` 暖白 | `#2f2a22` 墨色 |
| 强调色（按钮/进度环） | `#e8b04b` 赭黄 | `#cf5f45` 珊瑚 |
| 焦点环 | `#ffd166` 亮黄 | `#2f2a22` 墨色（**不用蓝**：蓝描在珊瑚色按钮上很脏） |
| 卡片 | `#fdf6ec`（与图片底色同色，看不出接缝） | 同左 + 描边 + 轻投影 |

**关键取舍：卡片底色必须等于素材底色。**
AI 图的背景是米色，深色主题下米色卡片正好融为一体；
浅色主题若把卡片做成纯白，图与卡片之间会露出一圈方块接缝。

切换方式是给 `<html>` 加 `data-theme`，零重绘成本；没手动选过时跟随
`prefers-color-scheme`。

### 4.2 答案区排版

```
cat  /kæt/     猫  māo
```

- 英文最大，音标紧随其后但**小一到两号**、颜色弱一档（不能和单词抢注意力）
- 音标与单词之间留 `clamp(6px,1.4vmin,18px)`，不能贴字
- 音标用斜杠包围，英式 RP 记音，与 TTS 的 `en-GB` 一致
- 中文与拼音成第二组，组间距 `3vmin`；手机上会整体换行居中

## 5. 无障碍清单

- [ ] 所有图片有 `alt`（用词条的 `zh` + `en` 拼接），装饰图用 `alt=""`
- [ ] 焦点环对比度 ≥ 3:1（对相邻色）
- [ ] 不用颜色单独传达信息（正确/错误同时有图标 + 位置）
- [ ] 倒计时变化对屏幕阅读器使用 `aria-live="off"`，避免每秒打扰；只播报"答案已揭晓"
- [ ] 支持 `prefers-reduced-motion`
- [ ] 文字缩放 200% 时布局不破（用 `rem`/`vmin`，不用固定高度裁切）
