# 06 Harness：本机 AI 协作工作台

本文定义 **AI coding agent 在本仓库里怎么工作**。它不是"给 AI 的建议"，是**约束**。
换一个 agent（WorkBuddy / opencode / Claude Code / codex / Cursor）进来，行为必须一致。

---

## 1. 为什么需要 harness

一个人 + 一个 AI 做小项目，最大的损耗不是写代码慢，而是：

| 损耗 | 表现 | harness 的对策 |
| --- | --- | --- |
| 上下文遗忘 | 新会话不知道上次为什么这么设计 | `docs/07-decisions.md` + `.workbuddy/memory/` |
| 规格漂移 | 代码改了，文档还是旧的，下次照着旧文档改回去 | docs 为唯一事实来源，DoD 强制同步 |
| 风格漂移 | 这次用框架、下次用原生，仓库变成拼盘 | `AGENTS.md` 硬规则 + ADR |
| 重复踩坑 | 同一个 TV 兼容问题踩三次 | 踩坑记进 `MEMORY.md` |
| 过度发挥 | AI 顺手重构、顺手加依赖 | 任务边界 + 禁止清单 |

**核心思想：把"人脑里的项目状态"外化成文件，让 agent 每次都能低成本地恢复现场。**

---

## 2. 三层文件职责

```
┌──────────────────────────────────────────────┐
│ AGENTS.md        路由层（地图）               │  ← 只放"去哪找"，不放细节
├──────────────────────────────────────────────┤
│ docs/            规格层（事实来源）           │  ← 稳定、结构化、可验收
├──────────────────────────────────────────────┤
│ .workbuddy/memory/  经验层（随时间积累）      │  ← 流水账 + 稳定的坑
└──────────────────────────────────────────────┘
```

**不许交叉**：

- `AGENTS.md` 里不写具体格式/字段定义（会与 docs 重复，必然不一致）
- `docs/` 里不写"今天做了啥"（日志不是规格）
- `memory/` 里不写验收标准（那是 docs 的事）

---

## 3. 会话启动协议（每次新会话，agent 必做）

```
Step 1  读 AGENTS.md                        （必做，约 200 行，成本可控）
Step 2  读 docs/README.md 定位相关文档       （按任务取，不一次全读）
Step 3  读 .workbuddy/memory/MEMORY.md      （长期约定与坑，必做）
Step 4  读最近 1–2 篇日日志                  （了解上次进度，仅在续做任务时）
Step 5  声明任务边界："这次只改 X，不动 Y"
Step 6  动手
```

> Step 5 是防止 AI 过度发挥最有效的一步。**用一句话说出边界**，
> 用户能立刻纠正，比改完再回滚便宜 10 倍。

---

## 4. 任务收尾协议

每个任务结束前逐项确认，缺一项不算完成：

1. **对照验收标准**：`docs/02-requirements.md` 里对应编号，逐条说"满足 / 未满足"
2. **三尺寸自检**：1920×1080 / 1024×768 / 390×844，各看一遍主流程
3. **离线自检**：DevTools 断网，功能仍完整
4. **控制台**：无报错、无 404
5. **文档同步**：改了行为 → 改 docs；做了决策 → 加 ADR
6. **记忆追加**：`.workbuddy/memory/YYYY-MM-DD.md` 追加一条，模板见 §6

## 5. 记忆规范

### 5.1 长期记忆 `.workbuddy/memory/MEMORY.md`

**只写会反复用到的东西**，控制在 300 行内，超了就要重构/删减。

适合写：
- 稳定约定（"题库一律不改 JS"）
- 架构决策的一句话结论 + 指向 ADR
- **踩过的坑**（"Android TV 上 `speechSynthesis` 存在但无声，不要用它判定流程"）
- 外部依赖的硬事实（浏览器版本下限、素材体积上限）

不适合写：今天的进度、临时路径、待办清单（那些进日日志）。

### 5.2 每日日志 `.workbuddy/memory/YYYY-MM-DD.md`

**只追加，不覆盖、不改历史**。一天一个文件。

### 5.3 何时写记忆

完成以下任一即写：
- 建/改了 `src/` 下的代码
- 改了题库结构或 schema
- 做了技术选型或推翻了旧方案
- 踩到坑并解决了（**这条最重要**，坑不记就会重踩）
- 用户表达了偏好或新的项目约定

## 6. 日志条目模板

```md
## 14:30 实现倒计时进度环

**做了什么**：新增 `src/ui/countdown.js`，SVG 圆环 + requestAnimationFrame 驱动，
倒计时结束派发 `question:reveal` 事件。

**改了哪些文件**
- `src/ui/countdown.js`（新增）
- `src/styles/components.css`（+.countdown-ring）
- `docs/03-ux-devices.md`（补进度环尺寸规范）

**关键决策**：用 rAF 而非 setInterval —— setInterval 在 TV 浏览器后台标签页会被节流，
导致倒计时与动画不同步。

**坑**：SVG `stroke-dasharray` 在 Safari 上需要用 `pathLength="100"` 归一化，
否则环长度算不准。

**待办**：进度环点击"立即揭晓"还没接，M1 收尾时补。
```

## 7. 技能（skills/）约定

`skills/` 存放**项目级**可复用能力，跨 runtime 优先加载（`AGENTS.md` 已声明路径）。

### 何时该建一个 skill

同一个操作被重复执行 ≥ 3 次，且步骤固定、容易漏步 → 抽成 skill。
典型候选：

| 候选 skill | 触发场景 | 内容 |
| --- | --- | --- |
| `add-vocab` | 新增词条 | 校验 JSON 格式 → 检查图片存在 → 检查干扰项不重复 → 注册到 index → 更新计数 |
| `check-bank` | 题库体检 | 遍历所有分类，校验 id 唯一、字段必填、素材路径存在、体积超标告警 |
| `verify-layout` | 三端布局自检 | 用固定三尺寸截图，检查溢出、焦点环、对比度 |

### skill 目录结构

```
skills/
└── add-vocab/
    ├── SKILL.md          # 触发条件 + 步骤 + 校验点（必需）
    └── scripts/          # 可选，辅助脚本
```

> **当前阶段（M0）先不建 skill**。等真正重复第三次再抽，
> 提前抽出来的 skill 往往是错的抽象。

## 8. Agent 禁止清单

| 禁止 | 原因 |
| --- | --- |
| 引入构建工具 / 框架 / npm 依赖 | 违反 ADR-001，会毁掉"改完刷新即生效"的体验 |
| 一次性重构多个模块 | 无法回滚、无法定位问题 |
| 顺手修改任务范围外的文件 | 制造 review 噪音与冲突 |
| 静默改变题目数据结构 | 题库是外部数据，改 schema 会让人已写好的词条失效 |
| 删除文档里的"待确认问题" | 那是给人看的决策入口，不是待清理的垃圾 |
| 用 `outline: none` 去掉焦点环 | TV 上等于键盘/遥控器完全不可用 |
| 为"未来可能用到"提前抽象 | YAGNI；本项目尤其容易过度设计 |
| 在代码里写中文界面文案 | 违反双语约束（答案数据除外） |

## 9. 人机分工

| 事 | 谁做 |
| --- | --- |
| 产品方向、是否加功能 | **人**（AI 只能提建议 + 写 ADR 草稿） |
| 素材挑选与版权确认 | **人**（AI 可给格式规范与命名建议） |
| 技术实现、文档维护、自检 | **AI** |
| 三端真机 / 真电视验收 | **人**（AI 只能做到浏览器尺寸模拟） |
| 记忆整理与日志蒸馏 | AI 起草，人确认 |

> 最关键的一条：**AI 不替人做"要不要"的决定，只做"怎么做"的实现。**
> 遇到需求冲突或范围膨胀，停下来问，不要自己拍板。

---

## 10. Harness 自身的维护

- 每完成一个里程碑，回看本文一次，删掉已经内化成习惯的条目（文档要瘦）
- `AGENTS.md` 保持 ≤ 300 行，超了就拆到 `docs/`
- 日日志超过 30 天，把有价值的内容蒸馏进 `MEMORY.md`，然后删除旧日志
- 本文与 `AGENTS.md` 冲突时，**以 `AGENTS.md` 为准**（它是入口，优先级更高），并修本文
