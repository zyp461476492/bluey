## 第二条线：Studio（生产端）

App 线（M0–M5）和 Studio 线（S0–S3）**并行但独立**。
Studio 不阻塞 App：M1 用现有 12 张打样图就能跑，Studio 什么时候好用什么时候接上。

| 阶段 | 目标 | 产出物 | 验收信号 |
| --- | --- | --- | --- |
| **S0 骨架** | 数据库与服务通 | Express + `node:sqlite` + 6 张表 + `seed` | `GET /api/words` 返回 12 条 |
| **S1 词条管理** | 能在网页里编题库 | React + shadcn/ui + 通用 DataTable：分类/词条 CRUD | 增删改一条词条不用碰 JSON |
| **S2 工单与入库** | 生成走流程 | outbox 工单 → agent 执行 → 导入 → pipeline | 12 张打样图走完整个流程进 `assets/` |
| **S3 发布** | 导出可信 | schema 校验 + 混源检测 + 覆盖率 + 导出 JSON | App 直接读导出结果就能玩 |

**S2 是唯一有技术风险的阶段**（跨了 Studio 与 agent 两次进程边界）。
卡住的退路：Studio 先只做"人工拖图入库 + 后处理 + 发布"，生成环节继续在对话里由 agent 跑。

**并行建议**：先做 M1（App 主循环），再做 S0–S1。理由——
M1 用现有素材就能验证"孩子愿不愿意玩"，这是整个项目最大的未知数；
Studio 的效率提升只有在"词条数 > 50、要反复换图"时才显现。
