# 11 题库设计：年龄分层与主题矩阵

> 本文定义**内容怎么组织**。素材怎么生产见 `09`，生产工具怎么建见 `10`。
>
> 一句话结论：**2 岁和 6 岁不是"同一套内容降低难度"，是两种不同的玩法。**
> 所以年龄档是**配置档**，不是内容分库。

---

## 1. 为什么必须先分层

先看两个孩子的差别：

| | 2 岁（24–35 月） | 6 岁（72–83 月） |
| --- | --- | --- |
| 理解词汇量 | 200–300 词 | 2500–3000 词 |
| 专注时长 | 3–5 分钟（一题 5 秒都可能太长） | 15–20 分钟 |
| 工作记忆 | 同时只能拿住 **1 个**对象 | 能同时处理 3–4 个 |
| 能做的交互 | 指、拍、翻页 | 选择、排除、读简单单词 |
| 不能做的 | 四选一、认字、理解"猜"这个规则 | — |

**关键判断：2 岁不做"猜"，做"认"。**

"猜"需要"我知道答案但你不知道"的心理理论，这个能力 3 岁后才逐渐成熟。
2 岁孩子玩的是**命名游戏**：大人指着一张图说"猫"，孩子跟着说"猫"。

所以 2 岁档不该有倒计时悬念，应该是**闪卡**：图 + 词 + 发音同时出现。
3 岁以后才进入"看图 → 想 → 揭晓"的猜词循环。

这条如果做错，2 岁孩子会在第一题就失去兴趣，而家长会以为"孩子不喜欢这个 App"。

## 2. 三个年龄档

| 档位 id | 月龄 | 称呼 | 玩法 | 倒计时 | 选项 | 文字 |
| --- | --- | --- | --- | --- | --- | --- |
| `toddler` | 24–47 月 | 幼儿（2–3 岁） | **flashcard** 闪卡 | 无 | 无 | 图词同时显示 |
| `preschool` | 48–71 月 | 学前（4–5 岁） | **reveal** 猜词 | 3s | 无 | 揭晓后显示 |
| `school` | 72–95 月 | 学龄（6–8 岁） | **reveal** + **quiz** | 5s | 4 选 1（可关） | 揭晓后显示 |

三档是**配置**，不是三套题库。见 §3。

> 档位可继续细分（如 3–4 与 5–6 分开），因为一切都是配置驱动，
> 加一档只需在 `age_profiles` 里加一行，不改代码。

## 3. 核心设计：年龄档是配置档

### 3.1 一份词库，三档复用

同一个词条 `cat`，在三档里呈现完全不同：

| 档位 | 画面 | 交互 |
| --- | --- | --- |
| toddler | 大图 + `cat / 猫` 同时显示 + 自动朗读 | 点一下 → 下一张 |
| preschool | 大图 + 3 秒 → 揭晓 `cat / 猫` + 朗读 | 点一下 → 立即揭晓 |
| school | 大图 + 4 选 1 + 5 秒 → 或直接判定 | 方向键选、确认 |

**所以不需要维护三套题库**——一套词条，三档配置，素材一份。

### 3.2 配置项（`age_profiles`）

| 字段 | toddler | preschool | school |
| --- | --- | --- | --- |
| `mode` | `flashcard` | `reveal` | `reveal` \| `quiz` |
| `revealDelayMs` | 0（立即） | 3000 | 5000 |
| `optionCount` | 0 | 0 | 4 |
| `showTextBeforeReveal` | 是 | 否 | 否 |
| `showPinyin` | 否 | 是 | 是 |
| `ttsRate` | 0.8（慢） | 0.9 | 1.0 |
| `maxPerSession` | 8 | 12 | 20 |
| `autoAdvanceMs` | 3500（自动翻） | 0（手动） | 0 |

`autoAdvanceMs` 是 toddler 档的关键：2 岁孩子不会主动点"下一题"，
**自动翻页 + 家长在旁边说**才是真实使用场景。家长想停就点一下暂停。

### 3.3 词条的 `minAge` 与 `difficulty` 是两回事

| 概念 | 含义 | 例子 |
| --- | --- | --- |
| `minAge` | 最早几岁可以引入这个词 | `elephant` → 2 岁就能认 |
| `difficulty` | 这个词本身有多难 | `elephant` 对 2 岁是难词（音节多、不常见） |

两者不等同，**都要有**：

- `minAge` 决定"这个词会不会出现在某档"（App 过滤）
- `difficulty` 决定"同一档内的出题顺序"（先易后难）

反例：`dinosaur`（恐龙）难度高，但 3 岁恐龙迷很熟 → `minAge=3, difficulty=3`。

读法：**201 条"档位×主题"引用，去重后只有 116 个不同的词。**

> 这张表的数字是脚本算的，不是估的。改数字请同步重算，别手改合计。

### 4.2 为什么不用"主题 = 分类文件"

`data/questions/<theme>.json`，每个 item 带 `minAge`。
App 按当前档位过滤 `minAge <= 当前档`，再按 theme 分组。

这样加年龄档不用动任何文件，加主题只加一个文件。**两个维度正交。**

### 4.3 主题命名约定

文件与 id 用英文单数/复数按习惯：`animals`（复数，可数集合）、`food`（不可数）、`colors`、`verbs`。
中文名只出现在 `name.zh` 里。

## 5. 各档玩法细节

### 5.1 toddler（2–3 岁）· 闪卡

```
┌──────────────────────────────┐
│         ┌────────────┐        │
│         │            │        │  图片占 70% 画面
│         │    图       │        │
│         └────────────┘        │
│           cat    猫           │  文字与图同时显示，字号极大
│         [ 🔊 再说一次 ]        │
└──────────────────────────────┘
        3.5s 后自动翻下一张
```

- **没有倒计时环**，没有"揭晓"这个概念，没有选择题
- 自动翻页，点任意位置暂停/继续
- 只显示一种语言（设置里选，默认中文）
- 一次最多 8 张，结束页是"再来一次"

### 5.2 preschool（4–5 岁）· 猜词

```
图 → 3 秒（进度环）→ 揭晓 cat/猫 + 朗读 → 手动下一题
```

- 3 秒而不是 5 秒：4 岁孩子的"想"很快，超过 3 秒会开始走神
- 揭晓后自动朗读，然后停下来等手动点"下一题"（**不自动翻**，让孩子有时间重复说）

### 5.3 school（6–8 岁）· 猜词 + 选择

```
图 → 5 秒 → 4 选 1（可选）→ 判定 → 揭晓
```

- quiz 模式可选关闭（有些孩子就喜欢自己说）
- 反向模式（M5 后）：看中文猜英文、看英文猜中文
- 干扰项从**同主题**抽（语义接近才有难度，见 Q-02）

## 6. 内容规则（按年龄的硬约束）

### 6.1 通用（所有档）

| 规则 | 原因 |
| --- | --- |
| **单主体**，且完整可见 | 多主体会让孩子不确定"要猜哪个" |
| 无文字、无字母（AI 生成尤其要注意） | 图上出现 `cat` 就等于泄题 |
| 主体占画面 60%–80% | 太小看不清，太满有压迫感 |
| 无背景故事 | 背景会抢注意力 |
| 不用真实照片（初版） | 与手绘风格冲突，且照片的认知负荷更高 |

### 6.2 toddler 专属

| 规则 | 原因 |
| --- | --- |
| **只选孩子生活里见过的**（奶瓶、鞋、球、狗） | 抽象词 2 岁无法处理 |
| 不用抽象概念词（情绪、方位、动词） | 认知未到 |
| 不出现恐怖/凶猛形象（蛇、鲨鱼、狼） | 2 岁会怕 |
| 每个词的画面尽量"实物比例正确" | 建立真实认知，不做夸张变形 |

### 6.3 school 专属

- 允许抽象概念（`angry` / `above` / `share`）
- 这类词**AI 手绘很难画准**，且容易画出歧义 → 优先走 ARASAAC 象形图或人工挑选
  （联动 `09` §2.3 与 `10` §7 的 `forbidSourceForCategory`）

### 6.4 一条容易被忽视的规则

**同一主题里不能出现"长得一样"的两个词。**
`horse`（马）和 `donkey`（驴）、`rabbit`（兔）和 `hare`（野兔）——
AI 手绘风格统一 + 全带笑脸，会让它们几乎无法区分。

对策：同一主题内做**视觉区分度检查**（Studio 的 phash 比对 + 人工过一遍），
区分度不够的词，初版直接不收。

**实际消耗**（原始预估 vs 实绩）：

| 批次 | 内容 | 张数 | 预估额度 | 实际次数 | 实际额度 |
| --- | --- | --- | --- | --- | --- |
| ① | 工程车 | 8 | 40–80 | 8 | 40–80 |
| ② | 水果 8 + 身体 8 + 交通 8 + 动物 3 | 27 | 160–320 | 30（重画 hair、mouth） | 150–300 |
| ③ | 衣服 6 + 食物 8 | 14 | 85–170 | 15（重画 egg） | 75–150 |
| ④ | 颜色 + 数字 | 9 | 55–110 | **0** | **0** |
| **合计** | — | **49** | **340–680** | **53** | **265–530** |

> 另加打样阶段 13 次（1 张风格锚 + 12 张）。
> **全程一次过率 59/61 = 96.7%**，浪费调用仅 4 次。
> 预估时按 85% 可用率做预算是安全的，实际会更好——但**不要因此重估得更乐观**，
> 下一批的题材若更抽象，废片率会回升。

**三个批次的共同结论**

1. **风格锚对一切物体有效**：机械（有棱角）、水果（无棱角）、身体部位（抽象）、
   衣物（平面）四类都验证过，没有出现风格分裂。
2. **失败的不是"画得难看"，而是"认不出来"**：3 次重画全部属于后者（hair/mouth/egg）。
3. **身体部位必须去脸**，否则答案变成"一个头"。

**批量生成 + 网格审查的工作流**（值得复用的做法）：

```
生成 8–14 张 → PIL 拼成一张带标注的网格图 → 一次目视全部
            → 挑出问题项 → 单独重画 → 再拼一次确认
```

比逐张看省 80% 的检查时间，且能立刻发现"风格是否统一"这个单张看不出的问题。



**两个可以完全不花额度的主题**（值得优先考虑）：

| 主题 | 现在的做法 | 不花钱的做法 |
| --- | --- | --- |
| 颜色 | AI 画 4 个色块 | **CSS 纯色圆**：矢量、零成本、永不跑偏。颜色本身就是答案的指称物，画得越"干净"越好 |
| 数字 | AI 画"N 个物体" | **CSS 网格排 N 个同一个 emoji**（🍎🍎🍎）：数量准确、零成本 |

这两个主题用 AI 反而是**负收益**——AI 很可能给色块加纹理、给数字图加背景，还得重画。
省下 9 张 ≈ 55–110 额度，且一致性更好。

**这是全库做完的真实成本区间。** 三件事由此可推：

1. 月度预算设 1500 左右可以覆盖全库，但要分 2–3 个月跑
2. P0 单独跑一次约 325–650，`school` 档可以延后到孩子长大
3. 超过预算时按主题降级到 OpenMoji，而不是停摆（见 §9）

> 额度预估的机制设计见 `10-studio-architecture.md` §7.3。

## 9. 降级策略对内容的影响

额度不足时按主题整块降级到 OpenMoji，**不要逐词零散降级**：

| 主题 | 降级优先级 | 理由 |
| --- | --- | --- |
| numbers / colors | **最后降级** | 数字和颜色用 emoji/象形图完全够用，风格差异影响最小 |
| body / clothes | 可以早降 | OpenMoji 的身体部位图标质量高 |
| animals / fruits | 尽量不降 | 这是核心吸引力，手绘版明显更好 |
| feelings / positions | **优先用 ARASAAC** | 抽象概念本来就该用象形图 |

这条决定了"额度不足"时的降级顺序：**先降抽象词，最后降核心名词。**
